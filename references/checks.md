# 机械检查清单（Checks）

按 L0 → L3 排列。每条给「怎么查」「命中了说明什么」「阈值」。

所有正则以 Python `re` 语法书写，`(?m)` 表示多行。

---

## L0-1 主体归属缺失

```python
r"(本章|本节)(研究|介绍|讨论|分析|使用|只使用|采用)(了)?[^。]{0,30}(方法|工作|框架)"
r"该(工作|方法|论文)(的)?(实验|结论|设置|数据)"
r"(Rationale|Hyperion)[^。]{0,20}(由|被)[^。]{0,10}(提出|发表)"
```

**含义**：方法章把作者自己的工作写成了外部对象。
**例外**：第 1 章综述、第 2 章相关理论里出现「X 等提出」是正常的；只有**方法章**（通常是第 3 章以后）命中才算 L0。
**判定**：方法章内命中 ≥1 次即报，需人工确认作者是否为该工作第一作者。

---

## L0-2 幽灵表图

```python
r"((?<!散列|哈希|符号)表中|上表|下表|(?<!特征|计算|网络|因果|关系|拓扑)图中|上图|下图|见表|见图)"
```

**方法**：对每个命中位置，取其前后 400 字符窗口，检查窗口内是否有 `\ref{tab:` / `\ref{fig:` / `表\ref` / `图\ref`，或紧邻浮动体环境（`table`、`figure`、`tabular`、`sidewaystable`、`wrapfigure`、`algorithm` 等）。若前后无紧邻环境且整章找不到对应的 `\label`，则为幽灵引用。
**注意**：计算机/AI 论文中「卷积特征图中」「反向计算图中」「网络拓扑图中」属数据结构/计算图名词，非论文浮动体插图，已做负向零宽断言排除。

更严的检查：

```python
# 章内所有 \ref{tab:xxx} 的 xxx 是否在本章有 \label{tab:xxx}
```

**判定**：正文说「表中」但本章无该表 → L0。若确实在别章，改为 `表\ref{tab:...}` 显式引用。

---

## L0-3 跨章悬空引用

用上一条的 label 归属法，跨章命中时检查是否写了章号或 `\ref`。

**判定**：只写「表中」而实际在别章 → L0（评委翻不到）。写「第 3 章表 3.1」→ 合格。

---

## L0-4 指标未定义

```python
r"(?<![A-Za-z])[A-Z]{2,6}(?![A-Za-z])"   # 抓大写缩写
```

**方法**：先按 `references/metric-registry.md` 填指标登记表，再对每个缩写查表。对表里没有的，排除数学公式、代码环境与符号表（`denotation.tex`），取正文各章首次出现位置，往前 300 字、往后 100 字，检查是否出现「全称」「表示」「衡量」「定义为」「越高越好 / 越低越好」。脚本会直接打印每个缩写的首现上下文，用于核对全称是否与原文一致。

**判定**：
- 表头出现但正文无定义 → L0。
- 有中文名但无方向（越大越好/越小越好）→ L1。
- 有定义但尺度（×100 还是 0–1）不明 → L0（会导致跨章误比）。
- **有全称但与原文不一致** → L0，且比缺定义更危险：评委按全称查原文会查不到，反像编的。英文全称必须逐字取自原文并附「源文件:行」。

---

## L0-5 数字与事实库不一致

**方法**：从 `FACTS.md` 一类登记表抽出所有数值，与正文逐一比对。

```bash
grep -oE "[0-9]+\.[0-9]+" chapter*.tex | sort | uniq -c | sort -rn
```

**判定**：正文出现登记表里没有的数值 → 疑似编造，必须回查；同一指标两处数值不同 → L0。

---

## L0-6 尺度混用

```python
r"(除以|乘以|换算|折算|归一到|归一化到)"
```

**方法**：检查是否有把不同协议的同名指标做算术。

**判定**：不同主干/不同测试集的同名指标（如两种 CSD 尺度）出现相除、相减、排名 → L0。正确做法是标注尺度、说明协议不同，**不做换算**。

---

## L0-7 浮动体乱序

**方法**：插图（`fig:`）、表格（`tab:`）、算法（`alg:`）分立编号，按前缀独立提取定义次序与引用次序。若某类别下某 label 的定义序号小于该类别前一个被引用者的定义序号，即为乱序。

**判定**：图号跳号（先引用图 3.9 再引用图 3.7）→ L0，需前移图块或改引用句。图与表属于独立计数器，不得跨类别交叉判定乱序。

---

## L0-8 编译残留

```bash
latexmk -xelatex -interaction=nonstopmode -outdir=build "main.tex"
grep -c "Overfull \\\\hbox" build/main.log
grep -c "reference.*undefined" build/main.log
grep -c "Citation.*undefined" build/main.log
```

**判定**：overfull > 0 或 undefined > 0 → L0。另检查未引用浮动体数量（正文有图但从未 `\ref`）。

---

## L0-9 盲审递刀（自曝其短 / 过度自贬）

```python
r"(未能(充分|有效)?(证明|解决|验证|覆盖|达到)|"
r"没有(开展|进行|实现|做)|"
r"并未(开展|进行|实现|做|验证|证明|探索|考虑|深入)|"
r"尚未(开展|进行|实现|做|验证|探索|解决|深入)|"
r"(缺少|缺乏)(消融|用户|对比|基线|验证|理论|支撑|证明|数据)|"
r"严重不足|效果(较差|不佳|欠佳)|性能(较差|不佳|欠佳)|表现(较差|不佳|欠佳|不尽如人意)|"
r"劣势在于|遗憾的是|致命缺陷|先天不足|"
r"(无法|难以)(保证|有效解决|应对|推广)|"
r"在.{0,10}下失效|"
r"坦白(而言|地说)|我们承认|"
r"泛化(能力)?(较差|不足|有限)|鲁棒性(较差|不足|欠佳))"
```

**含义**：作者在主要贡献、正文各章小结、方法陈述或实验分析中，直白承认某核心实验缺失、未能验证核心主张或效果欠佳，给盲审专家送上“工作不完整 / 核心主张未经证实”的直接枪毙把柄。
**判定**：
- 贡献节、正文小结或正文论述中命中 ≥1 次 → L0。
- **改法要求**：不得粗暴删除，必须改为**客观界定适用边界**。
  - 例：「Hyperion 没有开展人类偏好用户研究，缺少用户研究构成明确边界」→ 改为「本研究重点考察客观量化指标与专家定性对比，大规模人群主观偏好评测留待后续结合实际工业场景拓展」。
  - 例：「该框架同时标出尚未验证的跨方法迁移与联合评价问题」→ 改为「该框架明确了跨方法迁移与联合评价的理论边界与适用条件」。
- **例外**：最后一章「总结与展望」中规范讨论未来工作时，若表述克制、聚焦外部扩展条件（如算力/高分辨率泛化），可不算 L0。

## L1-1 拼稿痕迹

```python
r"两篇(论文|工作)?|合订|补充材料|补充实验|小论文|原始工作|原论文|原文(?!本)|"
r"受?篇幅(限制|原因|所限)|正文与补充材料|"
r"(?<!特征|词元|状态|向量|通道|张量|维度|一步|多头)拼接(?!并投影)"
```

**判定**：正文出现即 L1。中文学位论文应为单一完整成果，通篇不得出现“两篇论文”“小论文”“受篇幅限制”（会议论文残留）或“见补充材料”（学位论文只有“附录”）。排除张量拼接（`torch.cat`）等深度学习特征拼接。

---

## L1-2 内部代号 / 脚本残留

**通用形态**（学科无关，直接查）：

```python
r"[A-Za-z]:\\\\|/home/|\.py\b|\.ipynb\b|\.log\b"   # 路径与脚本文件
```

**项目词表**：成员代号、风格编号、提示词字典名这类命名每个项目都不同，写进 `terms.json` 的 `codename` 字段，例如 `["^sty\\\\d{2}$", "^kp\\\\d$", "^cnt\\\\d{2}$"]`。

**判定**：正文（非代码块、非原图标签）出现即 L1。处理方式是翻译成学术表述——编号改序数（「第 8 种风格」）、字典名改数量（「5 个测试提示」）、英文黑话改中文名。

---

## L1-3 翻译腔数学

```python
r"1/\d+\.\d+|/\s*\d+\.\d+\s*倍|\d+\.\d+\s*倍"
r"\d+%?\s*(提升|提高|降低|下降)\s*\d+\.?\d*%"
```

**判定**：
- 分母带小数（`1/2.5`）→ L1，改为「为其 40%」或「缩小到 1/2.5」。
- 相对/绝对百分比混用且未说明基线 → L0（会被质疑数字来源）。
- 同一段出现两个以上不同量纲的倍数（1.9×、2.5×、3.0×）→ 必须加一句口径对照。

---

## L1-4 英文裸术语

**通用判定**：正文里连续出现英文词（不是缩写、不是专有名词），且首次出现没有中文名或括注 → L1。

**项目词表**：把本领域容易裸用的词写进 `terms.json` 的 `bare_en`，例如 `["floor", "multi-shot"]`。没有词表时就人工扫每章首段。

**判定**：首现给中文名 + 括注英文，后续可只用缩写；全程裸用 → L1。

---

## L1-5 元写作

```python
r"值得(指出|说明|展开|注意|强调)|需要(分别)?(陈述|说明|讨论)|读者(可能|容易)|不应被理解为|本文因此"
r"(本节|本章|下面|后续)(将|会)(说明|给出|讨论|介绍)"
```

**判定**：命中即 L1。这是"告诉读者我要怎么写"而不是"写"。

---

## L1-6 模板残留

```bash
# 未被主文件 \input 的 .tex
# 非本校模板注释（校名、示例作者）
grep -rnE "(大学|University).*(模板|template)" tex/
```

**判定**：存在未引用的旧章文件、他校模板注释 → L1（源码送审风险）。

---

## L1-7 第一人称出戏（“我们”）

```python
r"我们(的|提出|设计|发现|认为|构建|采用|使用|观察到|注意到|引入|将|证明|推导|对比|选取|选择|总结|团队|工作|实验|模型|方法|框架|在此|进一步)"
```

**含义**：英文论文通常为多作者署名（习惯使用 We / Our），机翻拼入学位论文后通篇残留“我们提出”“我们的模型”“我们将……”，直接暴露多作者小论文机翻拼合痕迹，破坏学位论文独立完成的学术规范。
**判定**：正文（排除 `thanks.tex` / 致谢页与直接引述外部学者原话）出现即 L1。
**改法**：
- 「我们提出……」「我们的方法」→「本文提出……」「本文方法」
- 「我们观察到 / 我们发现……」→「实验表明…… / 实测观察到……」（切忌机械改为「本文观察到」，论文无主体知觉）
- 「我们将……引入」→「本研究将……引入」

---

## L1-8 机翻跳戏与非学术口语

```python
r"假装|口号|甩锅|硬凑|一锅端|顺便|毕竟|反正|"
r"其实(?!际|验|施|质|体|况|效)|"
r"文中(指出|给出|表明|提到|记为|所述)|"
r"在另一(套|台|项)|另一套实现|先前的实现|"
r"有趣的是|不幸的是|令人惊讶的是|众所周知|不难看出|不难发现|显而易见|"
r"直观上|直观来看|直观地说|简单来说|简而言之|"
r"正如(前文|文中所述|预期)|如我们所见"
```

**含义**：
- 随手翻译或口语化改写残留的情绪化词汇（如「假装超参数一致」「相互否定的口号」），极易被评委质疑学术严肃性。
- 直译英文常见副词从句（如 "Interestingly, ..." 直译为「有趣的是」，"As is well known" 直译为「众所周知」），充满机翻小论文痕迹。
- 直译英文论文的 "as shown in the paper" 为「文中给出/文中提到」，评委无法分辨是指本文还是参考文献。
- 排除「其实际效果」「其实验结果」等合法第 3 人称代词结构。
**判定**：正文命中即 L1。

---

## L1-9 跨论文环境泄漏

```python
r"在另一(套|台|项)|原始实现|原论文|原表|另一套实现|先前的实现"
```

**含义**：小论文 A 与 B 的运行硬件（如 A100 vs H200）、代码基座或基线版本不一致，正文漏出“来自另一套实现”“在另一台机器上”，暴露缝合断层。
**判定**：正文命中即 L1，必须显式补全硬件、环境与实验配置口径。

---

## L1-10 标记语言与占位符残留

```python
r"\*\*[^\*\n]+\*\*|```|(?<!\\)#{1,4}\s+|TODO|FIXME|TBD|待补充|待核实|XXX"
```

**含义**：大模型生成 Markdown 漏转为 LaTeX 语法（如 `**加粗**`、` ``` ` 代码块围栏），或审查/草稿阶段留下的 TODO 占位标记。
**判定**：正文命中即 L1（直接影响打印与送审印象）。

---

## L2-1 动词垄断

```python
for w in ["说明", "表明", "显示", "证实", "反映", "揭示", "体现", "验证"]:
    count(w)
```

**判定**：「说明」占分析性动词总数 >50% → L2。建议压到 30% 左右，其余按语义分散。

---

## L2-2 段末自卫

**方法**：按小节切分，取每个小节最后一句，统计以否定/限定收尾的比例。

```python
r"(并不意味着|不等同于|不能简单|不可|不应|而非|而不是|仅限于|不代表)[^。]*。\s*$"
```

**判定**：某章超过一半小节以否定收尾 → L2。改成正面界定。

---

## L2-3 否定转折密度

```python
r"不是[^。]{0,30}而是|而非|并不|并非"
```

**判定**：每千字超过 3 次 → L2。

---

## L2-4 特征连词与空泛升华

```python
r"综上所述|值得注意的是|不可否认的是|显而易见的是|不仅如此|总而言之|双刃剑|赋能|如同[^。]{0,10}一样"
r"具有重要的?(理论|实践|现实)意义|为后续研究提供(了)?(有益|重要)?(参考|借鉴)"
```

**判定**：命中即 L2，给出章节行号，直接删或改成具体结论。

---

## L2-5 AI 时空套话与空泛副词

```python
r"(近年来|随着).{0,15}(飞速发展|迅猛发展|蓬勃发展|广泛关注|日益增加)|"
r"扮演着.{0,8}(角色|地位)|不可或缺|举足轻重|作为.{0,10}(基石|纽带|桥梁)|"
r"毋庸置疑|不言而喻|全方位|多维度|深层次|系统性地|"
r"显著提升了?|极大程度地|注入了新的活力|开辟了新的道路|奠定了坚实的基础|"
r"如同一把双刃剑|如同双刃剑"
```

**含义**：大模型生成文本中最典型的高频虚词与宏大背景句，既无信息量又具明显 AI 味。
**判定**：命中即 L2，给出章节行号，删去宏大修饰，改为具体实验现象或客观事实。

---

## L2-6 AI 破折号堆叠

**方法**：统计全文全角破折号「——」及 LaTeX 三连字破折号「---」的出现频次与汉字密度。

```python
dashes = len(re.findall(r"——|(?<!-)(?:---)(?!-)", text))
density = dashes / len(re.findall(r"[\u4e00-\u9fff]", text)) * 1000
```

**判定**：每千字破折号 > 1.5 次，或单段连续出现破折号插入语 → L2。中文学位论文应尽量使用逗号、括号或另起一句陈述，避免破折号泛滥。

---

## L3-1 符号表漏项

**方法**：抽取正文 `$...$` 内的单字母符号（排除函数名、单位），与符号表条目比对。

**判定**：正文出现但符号表无 → L3。反向（符号表有但正文从不使用）也算。

---

## L3-2 数学变量未加 `$`

```python
r"(?<![\\$])\b[NKTnk]\s*=\s*\d"
```

**判定**：出现在正文（非公式环境）即 L3，编译后是正体，与斜体变量不一致。

---

## L3-3 封面与前置

人工检查：导师英文名、答辩日期、答辩地点、委员会主席、学号、学院名。

**判定**：留空 → 报"需作者填写"，不算缺陷但必须列出。

---

## L3-4 参考文献

```bash
# 条目数、被引数、未引用条目
```

**判定**：
- 有 bib 条目从未被 `\cite` → L3。
- 同一文献两个 key → L3（合并）。
- 只有预印本、无正式版 → 提示但不报错。

---

## L3-5 术语跨章分裂

**方法**：脚本内置对照核心近义/译名术语对（并在 `terms.json` 中支持自定义 `term_pairs`）：
- 「词元」vs「标记」
- 「提示词」vs「提示语」
- 「主干」vs「骨干」
- 「隐空间」vs「潜空间」
- 「风格迁移」vs「风格转换」
- 「保真度」vs「真实度」
- 「微调」vs「调优」

逐章统计各术语频次。若两篇小论文各自保留不同译名（如第 3 章只用“主干”，第 5 章突发使用“骨干”；或第 3 章写“提示词”，第 5 章写“提示语”），脚本自动输出章节分布对比。

**判定**：跨章存在不同译名混用 → L3。须在全篇统一为一种学术译法（首次出现可括注）。

---

## 运行方式

```bash
python scripts/audit_thesis.py "D:/path/to/tex"
```

脚本输出一份按 L0–L3 分组的 Markdown，可直接粘进报告模板。脚本只做机械项，**主体归属、语义矛盾、跨章指代仍需人工确认**。
